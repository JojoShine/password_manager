# 黑白灰内部页面视觉优化规范

## 目标

在不改变首页布局、业务流程和深色模式视觉方向的前提下，统一浅色模式内部页面与弹窗的表面层级、阴影、圆角和按钮样式。整体方向为克制的黑白灰质感，避免无意义的悬浮阴影、过大的圆角和零散的蓝紫装饰。

## 范围

本次调整包含：

- 应用设置页
- 浏览器扩展页
- 添加密码弹窗
- 密码生成弹窗
- 密码解密弹窗
- 导出选项弹窗
- 上述页面使用的浅色主题按钮、输入框、分组容器和图标操作状态

本次不调整：

- 首页的布局、密码列表和分类结构
- 登录页
- 深色模式的颜色方向
- 下载、保存、导入导出、加解密等业务逻辑

## 视觉基础

### 颜色

- 页面背景：轻微暖灰 `#F4F4F1`
- 主要内容面：`#FBFBFA` 或 `#FFFFFF`
- 主文字：近黑 `#181817`
- 次级文字：中性灰 `#6F6F6B`
- 边框与分隔线：`#D8D8D3`
- 弱背景：`#EFEFEC`
- 主操作：近黑背景、白色文字
- 红色仅用于删除和错误，绿色仅用于成功状态
- 内部页面不使用蓝紫渐变或多色功能标签

### 圆角

- 输入框、普通按钮和图标按钮：`6px`
- 页面分组与普通容器：`8px`
- 弹窗：`12px`
- 标签和数字徽标：`4px`
- 仅语义明确的状态标签允许胶囊形

### 阴影与层级

- 页面、卡片、设置分组、输入框和普通按钮均为零阴影
- 常规层级由背景色差、留白和 `1px` 边框表达
- 只有弹窗、下拉菜单等实际覆盖内容的浮层允许轻微环境阴影
- hover 使用浅灰背景变化，pressed 使用颜色加深或轻微透明度变化，不使用夸张位移和发光阴影

## 组件规则

### 按钮

- 主按钮：近黑实底、白字、零 elevation
- 次按钮：透明或白色背景、`1px` 中性边框
- 低优先级操作：文字按钮
- 危险操作：红色仅出现在文字、图标或确认按钮，不扩散到普通组件
- 图标按钮提供明确的 hover、pressed 和 focus 状态，避免裸图标悬浮在白色背景上

### 输入框

- 使用白色或弱灰填充与 `1px` 中性边框
- 默认、hover、focus、disabled 状态保持同一中性灰体系
- focus 通过深色边框和轻微背景变化表达，不使用蓝色外发光

### 页面分组

- 相关设置项放在同一分组内，使用分隔线而不是每项单独加卡片
- 内容区域设置合理最大宽度，避免桌面大窗口下横向拉伸
- 标题、说明和操作按钮保持稳定的垂直节奏与对齐

### 弹窗

- 弹窗使用 `12px` 圆角和唯一允许的轻微环境阴影
- 弹窗内部信息块优先使用弱背景或细边框，不嵌套多层阴影卡片
- 底部操作统一为次按钮在左、主操作在右；危险确认使用红色主按钮

## 实现方式

- 在现有 Flutter/Material 3 技术栈内完成，不新增 UI 依赖
- 在浅色主题中集中设置按钮、输入框、图标按钮和弹窗的基础规格
- 内部页面移除覆盖主题的零散圆角、渐变和阴影，并改用统一视觉常量
- 首页已有的局部样式保持不变，避免共享主题调整影响当前首页视觉
- 交互、数据和错误处理逻辑不做改写

## 验收标准

- 浅色内部页面不再出现无语义的卡片或按钮阴影
- 圆角遵守 `6/8/12px` 层级，不再所有组件统一使用大圆角
- 主按钮、次按钮、文字按钮和危险按钮层级清晰
- 应用设置页、浏览器扩展页和四类弹窗视觉一致
- 首页和深色模式无意外视觉回归
- Flutter 静态检查、组件测试和现有测试通过
- 典型桌面窗口尺寸下无布局溢出或交互失效
